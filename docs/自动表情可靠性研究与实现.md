# 1.5 自动表情：从选图到真实发送

本次修复针对“她说能发表情、回复经常只有鱼emoji，但没有实际图片”的路径。自动选图继续使用当前一次聊天模型，不新增识图、分类、向量服务或付费模型调用；用户仍可关闭自动配图、降低概率、选择仅应请求，或逐图停用。

## 查到的问题

旧版普通聊天只有模型原样输出内部表情标记时才追加图片；缺少标记就直接结束。发送工具又仅在用户明确索要、或确认紧邻的表情提议时允许执行，因此“我能发”“以后发给你”及鱼emoji都不会触发实际发图。插件启用且日志没有报错，不能证明这条业务路径已经走通。

实际SDK还区分人格的工具配置：`tools=None`允许活跃工具，`tools=[]`是空工具集。贴纸插件会在真实的明确请求中，只为本次请求补回自己已启用的发送工具，不把所有工具打开。普通自动选图走候选与标记，不依赖工具列表。真实SDK检查覆盖了这一区别，不能把零工具误认为插件加载失败。

## 一次回复怎样决定配图

1. 完整收到本轮消息后检查自动开关、场景、概率、冷却及本轮工具状态。连续输入由陪伴模块合并为真实事件，贴纸插件读取这份完整输入；概率一轮只抽样一次。
2. 向同次主模型提供最多12个本地候选，包含实际ID、标题、标签、文字描述、适用及避用场景。模型可选一个ID，也可明确输出`[大肥鱼表情:none]`弃选；弃选优先于其他图片标记。
3. 模型没有给出决定时，本地兜底必须同时满足双方文字中的清楚日常互动：问候、庆祝、简短亲密、晚安或轻松接梗。还须命中图片标题、别名或标签，并符合该互动的心情。仅有图片说明中的“开心”、仅有鱼emoji、泛泛回复、转述、引语和功能讨论都不足以触发兜底。没有充分证据就不配图。
4. 严肃求助、低落倾诉、正式任务、代码、链接和工具结果继续优先文字。用户明确标过“不合适”的场景不自动使用该图，收藏不能覆盖这一选择；上一张图片也不进入本轮自动候选。用户清除反馈后才恢复该场景自动使用。
5. 选中后验证本地资产并预留一个图片位置，仍没有把它算作发送成功。即将发送图片包时再次核对当前开关、会话插件许可、图库、启停、反馈及图片哈希。

“本地试选”继续仅展示标签命中项，并明确不识图、不理解同义语义。实际聊天的主模型有上下文判断，但可能出错；本地兜底是更窄的工程规则，不宣称具有人类情绪感知。默认35%和30秒冷却沿用用户可调设置，未伪称来自论文中的最佳值。

发送真实图片时可移除末尾独立的鱼emoji签名，保留“想吃🐟”这类句内含义；没有把所有emoji或原生QQ小表情删掉。文字、QQ Face和图片分别表达，避免一张图片之外还固定重复鱼尾缀。

## 标记、分条与回执

普通完整模型回复中，内部标记先存入当前事件的短暂选择记录，再从可见正文中移除，使正常会话历史和之后的记忆钩子看到清理后的文字。只有标记的特殊回复保留到最终装饰阶段处理，避免SDK因为正文为空而不产生回复；代码、链接和思考区中的示例文字不作为决定执行。

普通分条与主动问候共用图片预留与回执规则。文字第一条已经获适配器接受，不代表最后的图片包也已发送。只在包含该图片的实际包返回成功后记录使用次数；途中来了新消息、权限撤销或图片被停用／删除时，尚未发送的图片预留释放。超时或取消导致结果无法确认时保留冷却，不自动补发；适配器接受也不等于QQ对方已读。

这套路径面向桌面默认的完整模型回复。宿主原生流式分片、第三方自行发送或任意转发转换不等同这条路径，未在这里承诺所有第三方发送方式都自动支持配图，也不偷偷切换用户的流式设置。

## 有原因的本机诊断

高级配图状态可读取最后原因、时间和累计次数：概率未命中、场景抑制、模型弃选、缺标记且无匹配、候选被选择、冷却、图片校验失败、图片未发送、适配器接受或结果未知。数据保存在现有本机图库状态库中，只含有界原因名、次数和时间，不保存QQ号、聊天正文、个人图片路径或密钥。

“已选择”表示等待发送，“适配器接受”才表示实际发送调用正常返回；两者不能互相替代。历史记录可能来自早先会话，应结合显示时间判断。诊断写入失败不会阻止正常文字回复。

## 研究与成熟项目对照

- Zhang等人的[STICKERCONV（ACL 2024）](https://aclanthology.org/2024.acl-long.417/)将贴纸放入多模态共情回复研究，说明选择需要结合对话情境。本版借鉴这种问题划分，未复现其多智能体数据生成、PEGS训练或实验结果。
- Zhang等人的[Selecting Stickers in Open-Domain Dialogue through Multitask Learning（Findings of ACL 2022）](https://aclanthology.org/2022.findings-acl.241/)及[论文PDF](https://aclanthology.org/2022.findings-acl.241.pdf)分别建模对话历史、贴纸情绪和语义。它支持将情绪词与实际使用意图区分的设计方向，不证明本版少量关键词规则能达到论文模型的准确率。
- [Meme Manager固定提交的事件源码](https://github.com/anka-afk/astrbot_plugin_meme_manager/blob/ec80e0a12f7651e86276dfce247f9e05d136ad93/mixins/event_handlers.py)核对了准备图片与发送回执分离、按实际图片包确认使用和流式路径需另行适配。新增代码独立实现，未引入该项目的图床、自动收图或辅助模型。
- [dsh-meme原项目说明](https://github.com/yyh-001/dsh-meme)区分按气氛选图、原生IM图片、内部标记和发送方式。本版沿用可选择不发的方向，不使用强制每轮发图，也不把网页前端替图直接当成QQ已经发图。

这些资料提供架构与问题意识，不能代替本软件的实际行为测试。规则中的长度界限、候选上限、概率和冷却是工程／产品边界，后续需根据自愿真实试用调整。

## 验证方式

隔离回归覆盖日常自动问候与简短亲密、明确none、低落与正式场景、标签零命中、负反馈、上一张避让、热关闭、图片未发送及未知回执、原有30张素材、个人图库、投稿和独立素材更新。

`build/check_sticker_sdk.py`使用真实已安装SDK的人格准备函数、ToolSet、装饰钩子和Image序列化，验证空人格工具表、本轮显式工具补回、零工具自动配图、QQ小表情两种钩子顺序及主动选图。StarLoader的工具绑定状态在隔离环境中构造；发送端是本地记录器，没有真正向QQ发消息，没有请求模型，也不读取用户会话或凭据。它证明软件组件路径可用，不冒充真人长期使用试验或线上QQ送达验收。
