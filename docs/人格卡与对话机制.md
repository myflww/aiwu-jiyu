# 人格卡与真实聊天机制

五张完整预设随应用离线附带，均包含身份、性格、关系分寸、语言节奏、对话示例、群聊与正式场景规则。它们不是五个关键词标签，也不声称是某种全网人气排名。

自然朋友、经典肥鱼、元气搭子分别参考 linsport/dsh-whale-persona、Kaalia0912/dsh-whale-musume-persona、xin-1712/dafeiyu-persona 的完整人格资料并重新适配 QQ；温柔陪伴与冷静学伴是本项目原创。引用版本的 Git blob 记录于 assets/persona/cards.json，相关 MIT 原文随附。上游形象来源和独立美术权利仍按 THIRD_PARTY_NOTICES.md 处理。

适配时删去强迫每句话卖萌、绝不改变称呼、要求展示思维链和宣称现实经历的约束。预设改变表达，已有工具选择、QQ身份、设备授权、聊天记录和记忆库继续保留。切换前备份实际原人格，可以选择恢复；程序只更新固定“大肥鱼”人格的系统提示词，使用 AstrBot 原生管理接口让运行缓存与存储保持一致。

## 研究怎样用

- Zhang 等，ACL 2018，[Personalizing Dialogue Agents](https://aclanthology.org/P18-1205/)：以明确、持久的文字画像组织人格，而不是只加一句角色称呼。这里借用结构思路，不把其训练模型的成绩当成本项目效果。
- Coman 等，INTERSPEECH 2019，[An Incremental Turn-Taking Model For Task-Oriented Dialog Systems](https://arxiv.org/abs/1905.11806v3)：持续理解输入和何时接话是不同于生成回答的问题。本文研究语音与增量状态，不能由此推导 QQ 应等待多少秒；本项目的10秒来自用户提出的可调整产品默认值。
- Choi 与 Li，ICML 2024，[PICLe](https://proceedings.mlr.press/v235/choi24e.html)：人格表达可以用一致的上下文示例引导。这里加入多场景示例和反例，没有复现论文的概率比筛选或训练流程，不声称同等收益。

人格只是生成约束。连续短句收集、群内回应资格、去重、真实多条消息、表情发送、权限和实际回执均由程序承担。不能靠模型一句“我会分开发”代替消息机制。连续输入保留原文、顺序及媒体，由最后一个真实事件继续正常链路，不先用额外模型把消息有损概括。

## 参数与实际边界

默认从最后一条消息起等待10秒，持续输入有最长等待上限和容量上限，命令与需要立即处理的情况按收集器规则绕过。用户可以关闭或调整。群聊默认只回应明确叫到机器人的消息，轻度参与另行选择并受冷却与预算约束。它们是可解释的工程规则，没有经过真人大样本实验验证“最像人”。

自动化验收覆盖一致性、竞态、输入顺序、去重、媒体和权限；并不等于已测出对话自然度。主观体验需要在日常使用中看具体对话，继续调整提示词、模型选择与参数。没有为了验收自动发送私人 QQ 消息或调用付费聊天模型。
