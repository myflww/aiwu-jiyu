# 消息收集与群聊节制（1.5.0）

这次把“用户是否说完”“是否轮到鱼说话”“一段内容如何发送”分开处理。10秒是按本产品需要设置的可调等待值，并非论文证明的最优值。实现不增加句子判断模型、后台付费请求或另一份聊天档案。

## 已核对的资料

- [When to Talk, arXiv:1912.09879v1](https://arxiv.org/abs/1912.09879v1)：讨论根据上下文决定何时继续发言，启发将回复时机作为独立决策；没有据此声称固定秒数最佳，也没有移植其神经网络。
- [Talking Turns, ICLR 2025](https://machinelearning.apple.com/research/talking-turns)：其语音系统评估区分交接、打断与反馈，提示避免“有输入就立刻抢答”。语音实验的时间参数不能直接套用 QQ 文本聊天。
- [AstrBot 官方防抖需求 #8622](https://github.com/AstrBotDevs/AstrBot/issues/8622)：同会话连续消息与“图片后补一句说明”是实际社区需求。
- [advent259141/astrbot_plugin_debounce，固定提交 0d8aaaf3285d535b76e2878159a9a8679e81a3f5](https://github.com/advent259141/astrbot_plugin_debounce/blob/0d8aaaf3285d535b76e2878159a9a8679e81a3f5/main.py)：核对其完整性判断、缓冲、等待锁与旧响应抑制方法。该项目 AGPL-3.0；本实现只学习问题边界，没有复制代码、模型或提示词。
- [ctrlkk/astrbot_plugin_chat_buffer](https://github.com/ctrlkk/astrbot_plugin_chat_buffer/blob/master/main.py)，2026-11-04 阅读：其按会话取消等待任务并合并 prompt 的设计可作对照，但在 LLM request hook 等待无法满足本项目对真实媒体对象与成员分流的全部需要。该项目 AGPL-3.0；未复制代码。此地址未固定提交，不作为构建依赖。

## 真实宿主链路

本机实际安装的 SDK 是 **AstrBot 4.29.4**。核对 `core/pipeline/stage_order.py`、`waking_check/stage.py`、`process_stage/stage.py`、`method/star_request.py`、`method/agent_sub_stages/internal.py`、`respond/stage.py` 及 `platform/astr_message_event.py`。

收集发生在高优先级 AdapterMessage 监听器：已通过宿主的白名单、会话开关、安全检查和媒体预处理，尚未调用正常 Agent。每个真实事件在自己的监听协程中等待，最终只让最新的真实事件继续。既不伪造用户事件，也不重新入队，更不直接另调一次模型来回复。

缓冲键是 `(真实 UMO, 发言人 ID)`，群友甲乙不会被合成一位用户。缓冲保存完整原消息对象和组件引用，按到达顺序加入换行边界，不做摘要、图片重建或内容裁剪。旧事件通过 SDK `track_temporary_local_file` / `untrack_temporary_local_file` 把已登记的临时媒体所有权转交最终事件；最终事件的原生上下文退出时统一清理。

默认最后一条后等待10秒，每条新输入重置；从第一条开始最多30秒，最多12条，达到6000字或128个组件也立即结束等待。字数是停止等待的阈值，最后一条若超过阈值仍完整保留，不在词中间裁断。总共最多128个待收集会话；插件重载、事件取消、显式停止和命令会清理旧缓冲，不持久化等待队列以免重启重放。命令和明显紧急请求立即走原流程；“先别回了”等停止语句只取消待回复内容。

每次真实新输入产生按发言人隔离的到达 token。排队后的请求、发送前的最终结果和各实际分条均检查 token、会话、模型与插件开关。新输入只中断尚未发出的内容；已被适配器接受的消息不能撤回，也不因此自动重发。进行中的模型或工具执行不被描述为已撤销。

私聊也允许明确结束。只有完全由纯文字组成、最后明确说“不用回”“不用回复”“我先忙了，不用回”“先不聊了”等独立短句的输入才会关闭这次默认回复，不发送假“已读”通知，不请求模型。整组真实输入仍在宿主共享锁内以 user-only 写入正式会话；需要时用原生 API 新建会话，不伪造助手回答。存储失败只标为不可用，不声称已经保存。当前爱之屋来源协议的完整对话要求真实 user+assistant，没有 user-only 归档类型；这些结束输入保存在 AstrBot，不能声称已归档爱之屋。没有为此伪造助手、工具观察或永远等待最终答案的来源条目。命令、图片、引用、工具确认、“好／可以／收到”、疑问和引用别人的结束语不被一刀切吞掉。没有接入模型`[silence]`协议：宿主把空完成视为异常的边界尚不适合无痕接管，这次不加入随机沉默或第二次模型调用。

桌面保存的固定插件配置是显式热设置：验证成功的布尔 `enabled` 可以在同一已加载实例中由关转开；身份仍不热改。坏文件、删除文件、原生插件停用、会话撤权和退出均关闭消息处理、主动聊天及活动采样，不沿用缓存true继续运行。所有角色能力仍分别按自己的开关启用。

## 群聊规则

默认 `addressed`：只回应实际 @鱼、引用鱼、以配置称呼或宿主非空唤醒前缀开头的输入。@全体成员和普通群聊都不构成邀请。一个明确邀请后的连续片段可以在同一位发言人的当前缓冲内续写；@或引用其他人的消息不借用这次邀请。

`light` 是用户可选模式：在上述直接回应之外，只对提及配置称呼的相关短消息按概率参与。默认3%、每个真实群90秒冷却、滑动一小时6次预算，全部可调，不是研究最佳值。预算在生成前预留，失败仍占用，避免故障期间连续重试。0预算或0概率真正禁用额外参与，但不拦截明确 @与引用。计数按平台实例和**真实群号**计算，即使宿主 `unique_session` 为每位群友生成不同 UMO，也不会绕过每群预算。轻度参与计数只在本次运行内保存，重载会重置；待发内容不会重放。

本插件不改真实 UMO、QQ 发送目标、权限或群成员身份。宿主原有共同群历史仍由 AstrBot 管理；“不混人”指消息收集及打断状态不把不同成员拼成同一输入，并不假称为每人复制了独立私聊历史。

## 真实分条及重复修复

旧分条代码使用 `copy.copy(Plain)`。4.29.4 的 Plain 继承 pydantic.v1 BaseModel，浅复制共享 `__dict__`；设置第二段文本会把已规划的第一段和原文一起改为第二段。这正是“同一段重复发送”的一个可复现根因。现在深复制待修改的 Plain，保留 Image 的同一引用以便图像插件验证真实发送回执。

装饰 hook 不发送；它只包装该事件的最终 `event.send`。原生 RespondStage 随后发一次，包装器将合适闲聊转换为2–4次真实 QQ 发送。自然闲聊总长至少36字、每包至少12字，必须有完整句子或段落边界；因此40–70字的两句闲聊也可能分成两次，而“在／嗯”和单个长句不乱切。36/12是此次调整后的产品默认，并非论文最优值，分条频率仍遵守用户开关。所有原文、空白与顺序保持，正式、重要、严肃、不要分条、一条发完、合同、法律、财务、完整文稿等明确输入要求优先整条。整条 fallback 也先 claim 本次最终结果，重复 hook、并发 reentry 或后续结果重试不能追加原文。工具中间消息、代码、链接、表格、正式内容、任务长答维持完整；图片插件在每个真正 packet 的发送前后验证并确认自己的同一张图片，不把前面文字已发当成图片成功。

若用户在 AstrBot 中明确选择原生分段、流式、语音或文字转图，则由对应原生机制拥有发送，本分条器不再叠加第二层。原生分段的细则继续遵循用户在 AstrBot 的设置。没有把多段文字塞进同一条 QQ 消息伪装成分条。

## 验证

- `build/test_turn_taking.py`：尾沿重置、最长等待、阈值不截断、图片/引用顺序、临时文件转交、同群不同成员、命令/紧急/停止/停用/取消、重复 ID、会话撤权、所有陪伴能力关闭仍收集、@全体硬门控、light 冷却/预算/0值。
- `build/test_natural_bubbles.py`：真实 packet 规划、完整文字、普通整条与分条都不重复、新输入取消、任务保持整体、群友互不打断，以及图像 before/after 回调。
- `build/check_turn_taking_sdk.py`：实际 SDK ProcessStage、StarRequestSubStage、RespondStage 与 Pydantic Plain；用假的 Agent/适配器记录器证明一个缓冲只放行一次正常入口，确实发出不同的两包；同一40–70字短回复在自然闲聊发两包、明确重要正式要求下发完整一包。原生清理仍执行，原生分段与自有分条不会重复接管。无真实 QQ、网络图片下载或付费模型请求。

没有宣称通过真实 QQ 端到端发送测试；适配器接受也不等于用户已收到或阅读。
