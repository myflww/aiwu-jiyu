# 联网搜索与机器人QQ资料

大肥鱼生活能力随爱屋及鱼预装。网页搜索、资料管理、QQ空间三个开关分别控制，默认关闭。授权目标明确是配置的**机器人QQ小号**；主人自己的QQ号用于确认身份，不作为被修改目标。群聊、其他私聊账号和电脑管理员名单都不能借此管理QQ账号。

在2026年11月4日进行的只读核对中，本机安装的NapCat编译版本为 **4.18.42**，QQ客户端版本为9.9.31-49738，AstrBot为4.29.4。NapCat的package.json内0.0.1是包元数据，不能拿来当运行版本。本机AstrBot内置网页搜索当时关闭、提供商为Tavily，各搜索Key均未配置；检查只输出了开关、提供商名和密钥是否存在的布尔值，没有输出密钥。

## 搜索

默认实现请求Bing公开RSS订阅入口，解析实际RSS中的标题、链接和摘要，不抓取或伪造HTML搜索页。开发时使用中性公开词 `Python asyncio official documentation`，真实返回200、RSS格式和有效来源；新实现再次验证得到6条HTTPS来源。测试没有发送私聊原文，也没有调用对话模型。

微软曾在[官方RSS介绍](https://blogs.bing.com/search/2005/1/RSS-Feeds-for-Search-Results/)中说明 `format=rss`，同时指出它是可能改变的实验服务。如今能返回RSS并不意味着稳定API或可用性承诺。因此请求超时、被限流、变成HTML或格式不正确时，会明确说本次搜索未完成，不将模型已有知识冒充搜索结果。也不提供搜索引擎镜像或批量抓取功能。

可选SearXNG按其[官方Search API](https://docs.searxng.org/dev/search_api.html)发送表单POST，使用JSON输出。实例必须自行开放JSON；很多公开实例会关闭此格式。地址只能为公开HTTPS，不能携带账号密码、查询参数或片段，不能解析到本机/私有网络；不会跟随重定向。源码只实现协议适配，没有复制SearXNG的AGPL实现。[SearXNG项目](https://github.com/searxng/searxng)作为成熟方案及协议参考。

[AstrBot已有内置搜索](https://docs.astrbot.app/use/websearch.html)，可由用户另配其支持的提供商。本插件不默认启用另一套内置搜索、不把对话Key当搜索Key，也不更改已有提供商配置。DuckDuckGo Instant Answer不是可靠的任意网页搜索替代，因此未将它包装成通用查梗能力。

只传入工具收到的公开主题关键词，不拼入聊天历史、QQ身份、模型密钥或本机路径；明显账号号段/密钥/路径模式会拒绝外发。关键词1–200字、最多6条结果、摘要每条600字、响应512 KiB、socket超时8秒，另设共享的5秒间隔和每UTC日60次上限。这些数字是输入和公开服务使用的工程预算，不是心理研究得出的最佳聊天参数。真实关键词仍会交给所选搜索服务，不能用来搜索私人秘密。

搜索结果标记为不可信外部资料，只提供摘要和引用来源，不自动打开网页或执行其中的内容。账号写操作没有模型可调用的确认工具，须经下一条真实主人消息或本地预览确认。这结合了[OWASP关于外部资料、最小权限和人工核对的防护建议](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)，不宣称彻底解决所有提示注入。

## 已核对的QQ接口

按[NapCat官方接口文档](https://napneko.github.io/develop/api/doc)及[当前版本完整接口入口](https://napneko.github.io/api/4.18.42)，并对照本机已安装4.18.42的公开编译实现，采用以下固定参数，不开放任意API转发。

| 能力 | 接口及参数 | 结果要求 |
| --- | --- | --- |
| 读取自己 | `get_login_info`；`get_stranger_info(user_id=机器人QQ,no_cache=true)` | 两次身份都须匹配配置的小号，只输出昵称/签名等所需字段 |
| 昵称 | `set_qq_profile(nickname)` | 不传其他人QQ号，不改性别等字段；外层成功还须检查内核 `result` |
| 签名 | `set_self_longnick(longNick)` | 参数名是 `longNick`，不使用一些第三方封装中的 `long_nick` |
| 头像 | `set_qq_avatar(file='base64://...')` | 只从六种随附素材中选择，读取时再次核验PNG签名、大小和SHA256；不接受任意本机路径或图片网址 |
| 自定义在线状态 | `set_diy_online_status(face_id,face_type,wording)` | 固定基础图标和单行文案，预览后主人确认；会切为在线的自定义状态，不是兴趣标签 |
| 空间文字 | `send_qzone_msg(content,ugc_right)` | 预览正文与可见范围；真实返回非空 `tid` 才报告收到发布回执 |
| 个人标签 | 无已核验接口 | 明确不可用，指向QQ官方客户端，不编造成功 |

QQ空间当前只做纯文字；未实现图片动态、好友动态抓取或自动发表。范围映射为：仅自己64、好友4、所有人1，默认64。运行时查询 `get_version_info`，只有NapCat版本至少4.18.33才准备空间发布；此门槛来自已核对的版本文档，不表示更老版本一定不支持。服务若明确返回接口不存在，仍显示不可用并提供[QQ空间官方入口](https://qzone.qq.com/)。这项能力与微信朋友圈、手机操作权限无关。

本机未发现独立face_config.json文件，但已安装NapCat4.18.42的公开编译资源内嵌了329条同schema的QSid/QDes配置。选择其中四条基础静态记录：微笑QSid14、奋斗30、睡8、咖啡60，均没有动画或隐藏字段；固定face_type为接口schema中的标准类型1。这些是互操作所需的少量标识事实，没有复制整份配置或第三方实现代码，也没有宣称全部图标在所有账号上可用。**QSid不是传统QQ消息表情下标**，例如这里的微笑是14，不能误用0。

[NapCat官方接口列表](https://napneko.github.io/onebot/api)确认在线状态的真实字段为face_id、face_type、wording，不是words、faceId或faceType。内部调用会将status设为10、extStatus设为2000，因而预览必须说明“会设为在线”。图标只接受固定icon_id：smile、focus、rest、coffee，默认smile，不能传入任意数字ID。请求成功的OneBot data是字符串，空字符串是合法成功回执；未核验的null响应、超时或失败不能报告成功。没有为此执行过真实QQ修改。

界面的昵称40字、在线状态40字单行、签名200字、动态800字是本插件的保守输入上限，不是QQ官方长度保证；平台可能有更严格限制或审核。昵称和签名修改后尽量重读核对；回执已接受但尚未同步时如实显示。头像及在线状态显示或审核也可能有延迟。自定义在线状态是用户所说“标签”的一种可能理解，个人资料兴趣标签仍明确不可用。

## 核对、确认与防重发

准备只进行身份/服务能力读取并保存本机预览，没有远程修改。每条记录绑定主人QQ、机器人QQ与真实私聊UMO，10分钟过期。JSON确认须携带准确的draft_id、一次性confirmation_token及字面量true，不能同时换入新正文。QQ中的自然确认只接受主人下一条**独立、完整**消息“确认这次修改”或“确认发布这条动态”；转述、模型自己输出、群聊以及另一会话中的文字不算确认。同一会话若有多条未过期准备，须先取消多余条目或使用那一条的高级确认指令。

存储使用SQLite `BEGIN IMMEDIATE`，让桌面与插件进程领取同一条准备时只有一个成功，依据[SQLite事务文档](https://www.sqlite.org/lang_transaction.html)实现。先提交“正在执行”的领取状态，再发远程请求；超时、程序退出、最终记录写入失败都不会让同一确认再次发送。记录只在本机保存必要预览、有限回执和搜索次数，最多保留60条终态及8条待确认；确认后清空执行payload和token摘要，不保存QQ登录凭据或搜索词历史。

| 状态 | 含义 |
| --- | --- |
| verified | 成功回执后重读资料一致 |
| accepted | 收到成功回执；或空间返回真实tid，客户端显示仍需核对 |
| rejected | NapCat或QQ明确失败，不报成功 |
| unavailable | 当前接口明确不存在，提供官方入口 |
| blocked | 发送前账号、开关或素材核对未通过，没有发送写请求 |
| uncertain | 已尝试写请求但回执不确定，先在QQ核对，不能自动重发 |

确认前与每次实际请求前重新检查身份和开关，账号切换后停止操作。QQ运行时工具显式遵守AstrBot的plugin_set和每会话disabled_plugins；当前SDK对LLM工具的调度不能代替这一步检查。重新注入当前请求的工具也只限当前会话明确允许的本插件active工具，不会开启整个工具库。接口没有提供“仅当账号仍等于某QQ才修改”的原子参数，因此不能承诺抵御用户在最后一瞬间手动切换协议端登录账号；执行账号操作期间请保持机器人小号登录，回执后核对实际资料。取消仅撤销未执行准备，不伪称能撤回已发表内容或已更改头像。

## 验证范围

`build/test_life.py`使用隔离目录和模拟的搜索/QQ传输，覆盖类型和URL边界、真实格式解析、失败不伪造来源、目标账号核对、预览只读、内外层失败回执、同一确认防重放、并发领取、超时与缺tid、撤权、头像变化、会话绑定、过期和取消，以及在线状态固定QSid、空字符串成功回执和接口不可用。`build/check_life_sdk.py`在真实AstrBot4.29.4 SDK与全新临时根目录验证七个工具的schema、主人私聊/UMO、active工具请求合并、自然确认和热撤权。除中性公开搜索的单独只读验证外，测试没有调用真实搜索、QQ账号写接口或模型，也没有在私人运行环境中修改资料或发表动态。

所有适配代码为本项目原创，只使用公开协议约定；没有复制NapCat混合许可源码、AstrBot实现或SearXNG实现。插件遵循项目随附的非商业许可与署名要求。
