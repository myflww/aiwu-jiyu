# 小家自检、恢复点与真实操作记录

本页说明 1.4.0 的运行保障设计。数值上限属于本机存储与资源预算，不声称由陪伴实验确定。

## 一次只读体检

首页与诊断日志的“小家体检”汇总对话服务、QQ 登录、消息通道、模型配置、插件、主动任务、记忆连接及电脑授权。可以只看“为什么没有主动找我／没有配图／没有记住／不能操作电脑”。

体检只读取本机状态、现有配置及本机服务的状态接口，不发送测试 QQ、不调用聊天模型、不创建或整理回忆。`ok` 表示该项已有对应证据，`unknown` 表示没有足够证据；模型密钥可读取不代表余额、限流或服务连通性已经测试。插件配置开启也不等于完成一次真实调用；发送适配器接受不等于对方收到或已读。

检查结果只提供固定导航动作：前往首页、日志、设置、插件百宝箱、陪伴设置、配图素材、电脑权限或记忆小屋。结果中的文字和数据不会成为要执行的命令。

## 恢复点的范围

手动备份，以及用户明确点击“安装更新／安装匹配旧版”之前，会创建一个校验后的本机恢复点。备份失败时，不启动安装程序。保留最近 5 个有效恢复点；未知、不完整或其他本机资料的 ZIP 不会被当作有效恢复点，也不会按有效备份保留策略删除。

包含：

- 非敏感的陪伴节奏、分段、配图和部分界面偏好。
- 已安装且内容与运行中软件随包清单的大小、SHA-256 相符的插件文件。只涉及随包插件，不扫描或打包自行安装的插件。

不包含：QQ 身份与登录、模型 API Key、电脑授权成员、活动感知授权、爱之屋配对信息与绑定、聊天数据库、真实回忆、个人表情图片或任务审计。它是一份有明确范围的恢复点，不是整机或整个运行目录备份。

恢复必须在首页先关闭聊天服务，核对范围后明确确认；软件不会暗中停止正在使用的服务。恢复点必须属于当前这份本机资料、与当前软件版本相同，且插件内容仍与该版随包清单匹配。先为当前状态创建新的恢复点，再合并偏好与写回校验后的插件；陪伴与配图配置同步到当前运行目录，继续使用当前主人、QQ 和身份配置。每个文件通过同目录临时文件替换，写入失败时撤回本次已经完成的替换。

这能处理正常写入失败，不承诺操作系统突然断电时跨多个文件完全原子提交；恢复点仍可保留并重新核对。服务在运行时不恢复，避免替换正在执行的插件或打断真实任务。

## 与旧版软件匹配

跨软件版本时，可以明确选择“下载匹配旧版”。安装包只取自项目 GitHub 对应正式版本，执行与正常更新相同的大小、路径和 SHA-256 校验。下载完成仍须明确点击安装；恢复 ZIP 内永远不含要执行的安装器。

这是“准备并安装匹配软件版本，再恢复同版本设置”的分步操作，不是后台自动降级。旧版本如果早于恢复功能，应使用该版本已有的设置方式或重新安装当前版本；不能承诺旧版本具有后来新增的恢复入口。软件安装器与本机数据分离，模型密钥、QQ 登录、聊天与爱之屋数据库不会由本模块恢复成过期副本。

## 作品箱的真实操作记录

电脑插件 0.4.0 在有权限的工具开始执行时记一条“进行中”，返回时记“完成”或“未完成”。命令显示实际退出码，成功写入的作品可以打开。长命令通过工作线程运行，让异步消息处理与进度读取继续工作；桌面操作仍串行，并在排队后再次核对权限。

记录只含动作类型、时间、状态、允许的作品相对路径和有限结果，不记录请求原文、账号、命令文字、键盘输入或截图内容。保留最近 60 条，上限 256 KiB；超过 6 分钟仍没有完成记录的步骤标为“结果未确认”，不会假称任务成功，也不会仅凭缺少回执就断言失败。完成一个工具步骤不代表整个多步骤任务全部完成。

## 查阅依据与工程选择

- [TUF 规范 1.0.37](https://theupdateframework.github.io/specification/latest/)明确区分更新目标的可信验证与应用自行执行安装，并关注混合版本、回滚等风险。本版保留 GitHub 正式版本、固定文件名和 SHA-256 核验，对插件恢复再增加当前包清单的逐文件匹配；**没有实现 TUF 的角色签名、密钥轮换或完整客户端，不宣称 TUF 合规或已解决发布账号被盗问题**。
- [Python `os.replace`](https://docs.python.org/3.13/library/os.html#os.replace)用于同文件系统中的文件替换；[Windows ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)也说明单文件替换与备份的语义。这里独立实现白名单、读回校验、同目录临时文件和失败撤回，不把单文件替换扩大为跨文件事务保证。
- [Python `asyncio.to_thread`](https://docs.python.org/3.13/library/asyncio-task.html#asyncio.to_thread)用于把阻塞 I/O 移出事件循环。采用它是为了让运行命令期间仍能响应消息和查看实际进度，不是加速模型推理。
- 5 个恢复点、60 条步骤、6 分钟未确认阈值是工程界限：现有工具命令最长 300 秒，另给读取与收尾时间。它们可以在后续有真实负载记录后调整，不属于人的情绪或主动陪伴参数，也没有虚构相关论文依据。
