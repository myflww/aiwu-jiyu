# 1.4.0 表情图库：研究、实现与参数边界

本版保留原有文字模型自选表情，并补齐本地整理、显式反馈及独立素材更新。设计参考与代码实现分开记录，没有把别的项目的实验效果当成本软件已验证的效果。

## 参考资料

- Joachims, T. (2002), *Optimizing Search Engines using Clickthrough Data*, KDD 2002，[作者公开论文](https://www.cs.cornell.edu/people/tj/publications/joachims_02c.pdf)。论文研究相对偏好学习，讨论了点击受展示位置影响、不能直接等同绝对相关性的局限。本版据此把显式“不合适”、收藏和实际使用记录分开：使用次数用于最近使用排序，收藏只在同等匹配条件下作为偏好，不从没回复或没点某张图推断用户不喜欢。这里没有训练RankSVM，也不复现或推广该论文的搜索实验结果。
- [Meme Manager 固定版本说明](https://github.com/anka-afk/astrbot_plugin_meme_manager/blob/ec80e0a12f7651e86276dfce247f9e05d136ad93/README.md)，核对提交`ec80e0a12f7651e86276dfce247f9e05d136ad93`。多包管理、批量整理、标签主模型自选及资源差异预览是产品参考；未引入其图床、自动收图、向量服务、额外模型或运行时，新增代码独立实现。

## 本版采用的可解释规则

本地试选只展示标题、别名或文字标签实际命中的有界候选，不用零命中图片补满列表；没有命中就明确显示无候选，不声称理解同义语义。用户明确标记“不合适”后，相关度除以`1+该场景反馈次数`；收藏作为同分偏好。这是透明的工程规则，可以被用户撤销，不是论文证明的最佳公式，也不是看过画面后完成的视觉语义判断。运行时提供给当前模型的候选机制继续保留，由模型结合对话决定是否选图。

普通聊天和主动问候向当前同一次模型请求提供有限候选ID、文字说明、适用／避用场景及显式反馈；模型仍可不选图。严肃倾诉或任务场景会先避开自动配图，明确点图保留自己的权限与节流路径。主动图片包发出前重新检查同一预留、插件与会话许可、图库选择、启停和实际图像；停用、删除或内容变化后不会继续发送旧预留。

收藏、使用和反馈通过本机SQLite事务协调桌面与运行中插件。仅保存图片标识、时间／次数、收藏、场景及哈希会话范围，不保存本地试选文字或原始QQ标识。哈希范围用于区分本机偏好，不应称为不可逆匿名化保证。

## 导入与素材更新

批量导入最多20张，单张最多8 MiB、总原图24 MiB；ZIP最多20 MiB，并限制条目数量、展开容量和压缩比。路径穿越、链接、加密内容及异常大小在写入前拒绝。实际图片逐帧解码并重编码去除私有元数据；每个成功条目独立保存，重复图不覆盖原说明或重新启用，保存失败回收新建的孤立文件。

独立素材包只允许清单、图片和逐图原许可文本，不包含可执行插件文件。先读取官方正式发布并展示变化，再由用户选择下载、校验与原子切换；损坏包可重新检查并修复到新存储槽，原活动包和个人图在新包验证成功前保持不动。仅保留活动版本及两个旧缓存版本。已随软件附带的相同素材不要求再次下载，图片未变化但说明或许可版本发生变化也可以检测更新。

这些数量、容量、候选数和压缩比是资源与存储界限，不属于人类情绪或陪伴实验参数。后续可以根据自愿试用反馈和真实负载调整，不凭空给出“科学最佳”的结论。

## 验证范围

使用隔离临时图库、伪官方发布传输和真实AstrBot组件检查导入、去重、并发计数、作用范围、候选、回执、热关闭、图片删除、哈希异常、损坏修复及不执行下载代码。测试不向真实QQ发送消息、不调用付费模型，也不代用户投稿图片。

用户操作见[1.4.0使用指南](1.4.0使用指南.md)，维护者的数据包构建入口为仓库`build/build_sticker_materials.py`。
